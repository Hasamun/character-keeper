# Система навыков Character Keeper

Работа идёт по 8 этапам задания. Каждый этап заканчивается рабочим состоянием, тестами и проверкой сборки. Если в один цикл помещается не всё, работа останавливается на целом этапе, а оставшиеся этапы перечисляются явно.

## Что найдено при аудите
- Вкладка «Навыки» (`character.$id.index.tsx`, вкладка `skills`) — пока заглушка.
- Активные эффекты (`ActiveEffect` в `derived.ts`) привязаны к предмету через `sourceItemId`. `reconcileEffects` синхронизирует их с экипировкой.
- Тип `EffectKind` в `items.ts` уже включает характеристики, вторичные навыки, КБ, атаку, урон, сопротивления, уязвимости, доп. урон, состояния и особые способности.
- Разделы совместного доступа: bio, primary, secondary, inventory, notes, history со значениями none/read/edit. Те же правила дублируются на сервере в `valid_character_permissions` и `commit_character_section`.
- Применено 7 миграций (последняя — `0007`).

## Этап 1 — данные и расчёт прогрессии
- Новый модуль `src/lib/rules/skills.ts`:
  - `SkillDefinition`: название, тип (active/passive), описание, `levels: SkillLevelPatch[25]`. В каждом уровне — `ops` (add/update/remove по постоянному ID эффекта) и необязательная `exhaustionCost`; если стоимость не указана, она наследуется с прошлого уровня. У каждого уровня есть отметка «заполнено вручную / предложено ИИ / пусто».
  - `SkillInstance`: id, `templateId`, `templateVersion`, определение, уровень, XP внутри уровня, порядок, история личных изменений.
  - Таблицы XP хранятся целиком: по 25 значений для активных и пассивных навыков. Используются первые 24 перехода, а уровень 25 — предел.
  - Функции: `resolveLevel` (собирает итоговые эффекты уровня), `addSkillXp` (переносит остаток, останавливается на 25), `rankOf`, `costAt`, `exhaustionBand` (диапазоны 0–99 … 500+, без автоматических штрафов), `diffLevels`.
- В `Character` добавляются `skills: SkillInstance[]`, `exhaustion: number`, `skillOrder`. `normalizeCharacter` и импорт/экспорт (`transfer.ts`) заполняют значения по умолчанию и сохраняют новые поля.

## Этап 2 — общая система эффектов
- В `ActiveEffect` добавляются `sourceType` (item/skill/potion/other) и `sourceId`. Старые записи с `sourceItemId` читаются как `item`.
- `reconcileEffects` трогает только эффекты предметов, эффекты навыков он не удаляет.
- `deriveCharacter` учитывает:
  - пассивные эффекты навыков (их итоговый уровень);
  - активные эффекты навыков (один экземпляр на навык: обновление заменяет значение);
  - разбивку по источникам.
- Базовые значения и выбор кубика остаются на врождённых характеристиках.

## Этап 3 — «Мои навыки», применение, XP, истощение, журнал
- Подразделы «Мои навыки» и «Каталог». В «Моих навыках»:
  - поиск, фильтр и сортировка, ручной порядок;
  - компактные раскрывающиеся карточки: ранг, уровень, полоска XP, стоимость истощения;
  - «Применить» — только у активных навыков;
  - просмотр 25 уровней, корректировка XP с причиной, история, отмена последнего применения.
- Панель действующих эффектов навыков; краткая сводка на главной вкладке; блок истощения (ручное изменение, отдых, зелья).
- При значении 500+ (текущем или ожидаемом) — окно «Да / Нет». Отказ ничего не меняет.
- Таблица `skill_action_log`. Применение, XP, истощение и эффекты записываются одной серверной функцией в базе: блокировка героя, проверка `updated_at`, уникальный `operation_id` от повторов. Отмена — отдельная компенсирующая запись; она запрещена, если после применения были другие действия с этим навыком.

## Этап 4 — ручной редактор
- Отдельный экран создания: «Создать вручную» / «Создать с помощью ИИ».
- Редактор показывает итоговые эффекты выбранного уровня. Правка возможна для одного уровня, ранга или всех 25.
- Перед сохранением — список затронутых уровней и разница «было → стало».
- Черновик можно сохранить с неполными уровнями.

## Этап 5 — ИИ
- Серверная функция через Lovable AI (модель по умолчанию, строгая JSON-схема, ключ только на сервере).
- Режимы: полная генерация по описанию, «ИИ, предложи развитие» (заполняются только пустые уровни, контрольные уровни сохраняются), правка существующего навыка.
- Похожие навыки из каталога передаются как ориентир баланса.
- Ответ проверяется по схеме и показывается как «было → стало». Принять можно всё, отдельные уровни, отдельные эффекты или ничего.
- Предупреждения о чрезмерной силе не мешают сохранить навык.
- При ошибке черновик не меняется. Заготовленных ответов нет.

## Этап 6 — каталог навыков
- Таблицы `skill_catalog`, `skill_catalog_versions`, `skill_submissions` по образцу каталога предметов. Функции модерации в базе (одобрить / отклонить с комментарием / архивировать) пишут в `admin_audit`. Есть повторная отправка.
- Получение навыка — независимая копия с id и версией шаблона.
- Сравнение с новой версией и выборочный перенос изменений не сбрасывают XP и уровень.

## Этап 7 — передача, обучение, права
- Таблица `skill_transfers`: отправитель, герой-получатель, снимок навыка, режим (copy / teach_current / teach_novice), статус.
- Получатель принимает передачу, и создаётся копия без временных эффектов, истощения и истории. Доступа к герою отправителя получатель не получает. Передавать может только владелец.
- Новый раздел прав `skills`: none / read / use / edit.
  - В базе обновляются `valid_character_permissions` и `commit_character_section`.
  - На клиенте обновляются `normalizePermissions`, `projectShared` и интерфейс доступа.
  - Старые приглашения без поля `skills` читаются как none.

## Этап 8 — итоговые проверки
- Vitest: сценарии 1–16 и 18 из задания (чистые функции).
- Браузер на временных героях и втором аккаунте: сценарии 10, 11, 17, 19, 21, 22, затем удаление временных данных.
- Регрессия: 92 существующих теста.
- Итоговый отчёт: функции, файлы, миграции, результаты, ограничения, что не сделано.
