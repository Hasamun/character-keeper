# Шаг 6 — импорт, экспорт и резервные копии

## Цель
Добавить перенос персонажей и массовых наборов предметов, предварительную проверку файлов и ручные резервные копии. Сохранить формат персонажей, игровые правила и существующий способ сохранения в Lovable Cloud.

## Что подтверждено при проверке
- На странице списка есть импорт одного персонажа из JSON; совпадающий идентификатор заменяется новым. Предварительного просмотра нет, а сообщение об успехе появляется без ожидания сохранения.
- В меню персонажа есть экспорт JSON. Изображения предметов представлены путями к приватным файлам, поэтому такой JSON сам по себе не переносит картинки.
- Сохранение владельца проверяет доступ, пути изображений и версию персонажа. Массовые операции должны сохранять эти проверки.
- В дорожной карте следующий этап — расширенный импорт/экспорт и резервные копии; MCP остаётся отдельной задачей.

## 1. Страница «Перенос и копии»
- Открывается из списка героев; экспорт одного героя также доступен из его меню.
- Три раздела: импорт, экспорт, резервная копия.
- Выбор нескольких файлов и записей, предпросмотр персонажей и предметов, список ошибок и предупреждений.
- Ничего не сохраняется до явного подтверждения. После операции показывается фактический результат для каждой записи; успешное сообщение — только после подтверждения сохранения.

## 2. Форматы
| Формат | Назначение |
| --- | --- |
| JSON | Один персонаж, список персонажей, один предмет или набор предметов; поддержка прежнего формата персонажа |
| CSV | Массовые наборы предметов; скачиваемый образец с понятными заголовками, корректной обработкой кавычек и переносов строк |
| ZIP | Персонажи или наборы предметов вместе с изображениями и описанием состава архива |
| PNG/JPEG/WebP | Импорт изображений с явным назначением персонажу или предмету; экспорт карточки персонажа или предмета в PNG |

- Поля предметов со сложной структурой — эффекты, требования, история — сохранять в отдельных JSON-полях CSV, чтобы не терять данные при обратном импорте.
- Не распознавать характеристики из произвольной картинки и не выдавать визуальную карточку за полную резервную копию.
- Простому JSON без вложенных файлов явно обозначать отсутствие переносимых изображений; для полного переноса предлагать ZIP.

## 3. Проверка и дубликаты
- Проверять структуру до нормализации: неверные числа, неизвестные значения, повреждённые ссылки на предметы и недопустимые изображения показывать, а не молча исправлять.
- Допустимые преобразования старого формата показывать как предупреждения; игровые расчёты не менять.
- Дубликаты отмечать внутри загружаемого набора и относительно выбранного назначения. Совпадение имени — только возможный дубль, не основание для удаления.
- Для персонажей: пропустить, создать отдельную копию или явно заменить своего существующего героя. По умолчанию не перезаписывать.
- Для предметов: пропустить или добавить экземпляр через существующие правила инвентаря. Снаряжение остаётся независимым; объединение расходников — только по существующему правилу совпадения свойств.
- При создании копии переназначать идентификаторы и связанные ссылки: экипировку, комплекты оружия, пояс и активные эффекты. Не восстанавливать заряды и не менять состояние эффектов.

## 4. Массовые наборы и каталог
- Набор предметов можно добавить в инвентарь своего выбранного персонажа.
- Отправка набора в общий каталог создаёт обычные предложения и проходит существующую модерацию; импорт не публикует предметы автоматически.
- Замену персонажей и восстановление копий ограничить собственными героями. Общих персонажей не включать в полную копию и не использовать для обхода прав по разделам.

## 5. Ручная резервная копия
- Скачать ZIP всех или выбранных собственных героев: характеристики, навыки и опыт, заметки, история, деньги, предметы, экипировка, заряды, активные эффекты и изображения.
- Перед созданием копии дождаться текущих сохранений и прочитать подтверждённые данные из Lovable Cloud.
- Восстановление проходит через тот же предпросмотр и выбор действий для дубликатов. Существующие герои не удаляются.
- Не включать пароли, роли, блокировки, приглашения и права участников. Новые копии героев не наследуют совместный доступ; замена данных собственного героя не изменяет его текущие права доступа.
- Недоступные картинки показывать отдельно: не объявлять архив полным без них. Скачиваемый архив содержит личные данные — предупредить об этом перед сохранением.

## 6. Надёжность и безопасность
- Ограничить размеры файлов, количество записей, размер распакованного архива и параллельные загрузки; показывать прогресс и разрешать отмену между записями.
- Отсекать небезопасные пути ZIP, вложенные архивы, неподдерживаемые типы и попытки доступа к чужим изображениям. Не загружать произвольные внешние ссылки из импортированного файла.
- Изображения из архива загружать как новые собственные файлы; при неудачном сохранении удалять только файлы этой операции.
- Повторно проверять доступ и версию непосредственно при записи. Конфликт сохраняет предпросмотр для повторного решения, без молчаливого перезаписывания.
- Массовую операцию показывать как набор независимых подтверждённых сохранений: при частичной ошибке не выдавать весь набор за успешно импортированный и не дублировать уже сохранённое при повторе.

## Техническая реализация
- Разбор и упаковка файлов — браузерными библиотеками для CSV и ZIP; тяжёлую обработку вынести из основного потока интерфейса.
- Проверка, обнаружение дублей и переназначение ссылок — отдельные чистые функции с тестами, рядом с существующими правилами. Использовать текущие нормализаторы только после явной проверки.
- Запись персонажей — через существующий `CharactersProvider` и защищённые серверные функции с проверкой версии; не вводить второй источник персонажей.
- Каталог и изображения — через текущие проверки доступа и модерацию. Новые постоянные таблицы для резервных копий не требуются: копии скачиваются пользователю.
- Обновить дорожную карту, правила архитектуры и описание новой страницы; сохранить русскоязычное тёмно-золотое оформление.

## Проверки перед завершением
- Тесты: прежний JSON, наборы, ошибки, CSV со сложными полями, дубликаты, переназначение всех ссылок, состояние зарядов и эффектов, ограничения ZIP и пути изображений.
- Проверить обратный перенос JSON/CSV/ZIP без изменения игровых данных и производных характеристик.
- Войти в приложение и пройти сценарий на временном герое: экспорт с картинкой → предпросмотр → импорт копии → перезагрузка → проверка данных и картинки → повторный импорт с выбором пропуска.
- Проверить конфликт версии, ошибку загрузки с очисткой файлов, запрет записи чужого героя и запрет обхода модерации.
- Проверить полный резервный архив и восстановление, экспорт PNG, отображение на узком и широком экранах; удалить временные проверочные данные.

## Не входит в этот этап
MCP, автоматические резервные копии по расписанию, распознавание характеристик с изображений, изменение игровых правил и массовая замена общего каталога.
