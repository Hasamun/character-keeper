## Skills system rules
- Acquired skills live in character JSON (`skills`, `exhaustion`) with pure progression rules in `src/lib/rules/skills.ts` (25 levels of add/update/remove patches, separate XP tables); skill active effects reuse `activeEffects` with `sourceType: 'skill'` and are never equipment-bound — one effect pipeline, equipment sync cannot drop them.
- Skill apply/XP/exhaustion/undo run through `skillAction` (pure `performSkillAction` + DB `commit_skill_action`): one locked, version-checked, op_id-idempotent commit of character JSON and `skill_action_log`; undo writes a compensating entry — journal and character never diverge.
- AI skill generation runs only in server function `generateSkill` (server-held key, up to 3 similar catalog skills as balance examples) and returns an unsaved proposal; AI and catalog proposals are reviewed in `SkillProposalReview` and merged by pure `mergeSelection` (whole/rank/level/single effect) — nothing persists without the normal editor save.
- Skill catalog is separate from personal skills; moderation goes through SECURITY DEFINER functions with admin_audit; a trigger snapshots every template version into `skill_catalog_versions`; copies carry `templateId`/`templateVersion` and are never auto-updated — users pull changes selectively, keeping level/XP.
- Effect lifecycle (`instant|sustained|gm`) is separate from `automation`; only `sustained` skill effects enter `activeEffects`, unspecified ones never auto-activate, and apply resolves effects/cost at the pre-XP level — prevents false active markers and same-use level-up boosts.
- Shared `skills` section (`read|use|edit`, `use` = apply/undo) covers skills/exhaustion/skill effects; commits merge activeEffects by sourceType; member actions go through service-role `commit_skill_action_member` and never return the full character — no section leaks.
- Teaching never modifies the sender: own heroes get one version-checked write, other players a server-snapshotted `skill_transfer_offers` row accepted atomically by `accept_skill_offer` — no client rollbacks.
